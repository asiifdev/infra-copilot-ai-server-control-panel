# Changelog

All notable changes to this project are recorded here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project intends to follow
[Semantic Versioning](https://semver.org/) once there is a release.

The changelog is kept in English only, as a single source of truth, so the two language versions
cannot drift apart. Release notes may get an Indonesian summary.

## [Unreleased]

### Added

- Running approved actions (ADR 0037, schema version 10). The new crate `actions` holds the closed list of actions (restart a systemd service, tier 2, fixed by code), their strict JSON form, canonical hash and an argv-only executor behind `transport::Runner`. `POST /api/proposals/{id}/execute` runs an approved, unexpired proposal on this machine once (one execution per proposal, never repeated by itself; the action, its hash, tool and tier must match what was approved; start and finish are hash-chain audited). Execution is **off** unless `infra serve --enable-execution` is used. The assistant gets the tool `propose_restart_service` (tier 1: it only writes a pending proposal). Tested with fake runners only; no test touches a real service. The web UI gets a Run button on approved proposals (with a confirmation that says exactly what will happen, a disabled state with a hint while execution is off) and shows the prepared action and the result of each run (282 web tests).
- Approvals and a redesigned web UI (ADR 0034, 0035). A person can approve or reject a pending proposal (`POST /api/proposals/{id}/decision`, one conditional update plus a hash-chained audit entry in one transaction; 409 `proposal_decided` / `proposal_expired`). Approving only records the decision: nothing is executed yet. The web UI gets a new shell (grouped sidebar, mobile menu), a Ctrl/Cmd+K command palette, a dashboard overview, an Approvals page with a live count, skeleton loading, a modern chat and a plan timeline, with no new dependency (254 web tests, axe checks in two languages and themes).
- Transport endpoint policy (ADR 0033): `TransportSpec::check_endpoints` refuses loopback, private, link-local, metadata and disguised addresses and internal names on shared infrastructure; the owner's own network is unrestricted. DNS-resolution checks belong to the future runner.
- Performance budget for the real binary (ADR 0032). `TARGET=infra scripts/measure.sh` measures `infra serve` with the embedded web UI (macOS: 5.8 MB binary, 10 MiB idle RSS, 19 ms to first response, 44.9 KB gzip UI) and `BUDGET_PROFILE=infra scripts/check-budget.py` checks it against the new `infra` block of `docs/perf-budget.json`; the CI `perf-budget` job runs both. Linux numbers await the first CI run.
- Local web server and web UI (ADR 0029, 0030, 0031). The new crate `server` (axum, tokio, rust-embed) serves a JSON API under `/api` and the UI embedded from `web/dist`, started by the new command `infra serve [--port N] [--db PATH] [--org SLUG]` (default port 7878). It acts as the owner of the local organization (single user) and binds loopback only: any other address is refused. It prints a one-time sign-in address `http://127.0.0.1:PORT/#t=<token>` (256-bit token, valid 10 minutes, single use, kept in the URL fragment so it is never sent to the server). Session cookie `HttpOnly; SameSite=Strict` (8 hours of inactivity, at most 5 sessions), `Host` must equal the bind address, changing requests need a same-origin `Origin` and an `X-Nodivara: 1` header, strict security headers including a Content-Security-Policy, JSON bodies capped at 64 KiB. No endpoint returns a secret: provider keys are only accepted and sealed in the vault. There is no TLS and no real login: sessions end by idle timeout, sign-out or restart, and a signed-out user restarts `infra serve`. The message catalog route `GET /api/i18n/{locale}` is public (UI texts only) because the sign-in page needs it before a session exists; this differs from the first reading of ADR 0029 and is noted in ADR 0029 and 0030. Tested over real sockets (`crates/server/tests`, `crates/cli/tests/serve.rs`).
- New crate `bootstrap`: the setup helpers that lived in `crates/cli` (database location, owner-only files, the single local organization and its owner, the vault from the environment, adding and removing providers with sealed keys) moved into a small crate shared by `cli` and `server`. CLI output and exit codes are unchanged.
- The web UI in `web/` (Svelte 5 + Vite + TypeScript, no SvelteKit, no runtime dependencies): Overview, Nodes (with inventory), Findings, Assistant (streaming chat with tool chips), Plans (draft text, steps table and gates; no approve or run), Transports, Memory (approve or delete notes), Settings (provider form, a "Test connection" button, language, theme). All texts come from the Rust catalog (`ui.*` keys in `en.txt` and `id.txt`, 304 keys), English and Indonesian, light and dark. 214 tests (`npm test`, including axe-core checks of every page in two languages and two themes and a replay of recorded real server answers); `npm run check` has 0 errors and 0 warnings. Production bundle about 131 KB of JavaScript (41 KB gzip) and 15.5 KB of CSS (3.2 KB gzip). Checked in Chromium (light and dark, 375 px wide, keyboard); not checked on real Windows high contrast or with a real screen reader. `web/public/favicon.svg` is a temporary redraw of the mark, not an official brand SVG.
- Scripts: `scripts/build-web.sh` (npm ci, check, test, build), `scripts/demo-serve.sh [--fake-ai]` (throwaway demo data, optionally with the loopback fake AI provider `scripts/fake-openai.py`), `scripts/smoke-serve.sh` (smoke test of the real binary) and `scripts/check-secrets.sh` (local gitleaks pass over unpushed commits and uncommitted files).
- CI: a `web` job (type check, tests, production build, bundle sizes, building the binary with the UI embedded, and the smoke test). `scripts/check-docs.py` now also fails when a crate is missing from the READMEs or `CLAUDE.md`, when a document quotes a schema version other than the latest migration, or when a known stale phrase returns.
- Test totals: 843 Rust tests pass and 1 is ignored (the live-provider test) in `cargo test --workspace`, plus 214 in `web/`. The schema is still version 9.

- CLI `plan` and `transport` commands (ADR 0028): `infra plan draft|list|show|gates` shares its code with the AI tool (`agent::plan_flow`); there is no approve, schedule or run command, and `plan gates` exits 1 while the cutover is blocked (an open critical finding, or missing, stale or incomplete evidence). `infra transport add|list|show|remove|check` reads credentials only from stdin (`--credentials-stdin`, `name=value` lines, never an argument) and seals them with the vault. `transport check` is a dry run by default: it prints the command plans with secrets masked and executes nothing; only `--run` executes them through `ProcessRunner` on this machine. The product never installs rclone, it only offers help. There is no command yet to update a transport's credentials (remove it and add it again).
- M3-c, AI planning tools (ADR 0027): the agent seams `PlanStore` and `PlanSink` with database-backed implementations; the tier 1 tool `draft_migration_plan`, which can only write a `draft` plan; and the tier 0 tools `show_plan`, `list_plans`, `check_plan_gates` and `list_transports`. The assistant registry now holds 14 tools. No tool can approve, schedule or run anything.
- M2-e, memory, search and the `infra` command line (ADR 0026, migration 0009): tables `memories`, `search_docs` and an FTS5 table `search_fts` kept in sync by database triggers (no application code writes the index; the query text from a model is split and quoted, never passed to `MATCH` as is). The tier 0 tools `search_inventory` and `list_memories` and the tier 1 tool `remember`, which only creates `pending` memories: a pending memory is never shown to a model or indexed, and only a person can activate it (`infra memory approve`). The system prompt gets an "organization notes" block (at most 20 active notes, 4 KiB, fenced as untrusted data). New `infra` commands: `init`, `node add`, `collect --save --node`, `compare --save --source-node --target-node`, `provider add|list|remove` (the API key comes from stdin or `NODIVARA_PROVIDER_KEY`, never an argument; the master key from `NODIVARA_MASTER_KEY`), `ask`, `memory list|pending|approve|delete`, and the global `--db`, `--org` and `NODIVARA_DB`. Exit codes: 0 success, 1 critical finding or cutover blocked, 2 usage, configuration or I/O error, 3 assistant or provider failure. The CLI acts as the organization owner (single-user local mode; there is no login). Schema version is now 9; 711 workspace tests pass (1 live-provider test is ignored and has never been run).

Migration 0008 adds `migration_plans` and `migration_steps`, with database triggers guarding `decommission_source`. The `draft_migration_plan` AI tool (M3-c) and the `infra plan` command (below) came later.

### Security

- rclone options are two disjoint sets per backend (`RemoteKind::plain_options` and `credential_options`). A credential name such as `secret_access_key`, `token`, `pass` or `key` is refused as a plain spec option, so `infra transport add --options secret_access_key=...` can no longer put a secret into the argument list (visible in process lists) or into the stored configuration in plaintext; credentials are accepted only through `--credentials-stdin`, sealed in the vault and passed in the environment. Covered for every backend by tests, including the CLI path and the raw database bytes.
- Review fixes for the runner, membership and plan: the process runner's timeout no longer depends on the pipes reaching end of file, so a child that keeps a pipe open cannot hang it; a conversation turn now also requires a current membership of the user in the organization; rclone options are checked against a per-backend allow-list; the plan rejects an exclude pattern that matches everything and checks that the spec's nodes and stored rows agree.

- `RootFs` now resolves every path with a directory-descriptor walk (`openat` with `O_NOFOLLOW` per component, links expanded inside the root with `readlinkat`, at most 40 links) and, on Linux, `openat2(RESOLVE_IN_ROOT | RESOLVE_NO_MAGICLINKS)` first. A process that can write inside the root can no longer swap a parent directory for a symlink between the check and the open (closes the limit accepted in decision 0013; decision 0017). The new `rustix` dependency (features `std`, `fs`) is used only by `collectors`; the public API is unchanged and `read_to_string_nolink` no longer needs a check-after-open.
- `env_ref` extraction ignores variables named like credentials (`PASS`, `SECRET`, `TOKEN`, `KEY`, `AUTH`, `CRED`, `PRIVATE`), trusts a bare `host:port` only for reference-named variables, and discards URLs whose userinfo was cut by an unencoded `/`, `?` or `#`, so a username or password digits can never become a host or port.
- `RootFs` never opens a device node for a file read: on Linux the entry is opened with `O_PATH`, typed on that descriptor and reopened through `/proc/self/fd` only when it is a regular file (falling back to the walk where `/proc` is missing); the walk checks the type just before opening, and the opened descriptor is checked again. File reads also use `O_NOCTTY`.
- PM2 collector refuses symbolic links at `.pm2` and at the dump, reads `/root` first and records the owning account, so a user-writable home cannot redirect the read or shadow the administrator's apps. The dump is opened with a check after open (`RootFs::read_to_string_nolink`), so a link swapped in between the check and the read is refused too; parent directories remain a documented limit (decision 0013).
- Redaction now treats `PASS` and `AUTH` named values as secrets, and collectors hide separate-argument secrets in process command lines and cron commands (`-p secret`, `--password x`, `curl -u user:pw`). Found by independent review, covered by tests.
- Redaction of nested quoted commands (`sh -c '...'`), `--user`/`--proxy-user` values and cron hints; `infra compare` sanitizes control characters from untrusted inventories so they cannot repaint the terminal or forge report lines.
- Collectors resolve symlinks inside the chosen root only, so a symlink in a mounted or untrusted tree cannot read host files; a crontab or process name with multi-byte characters can no longer make the whole collection fail.

### Changed

- The first AI provider added to an organization becomes its default automatically (CLI and server).
- The written migration plan names nodes and transports instead of ids.
- Streamed assistant text is redacted so that the pieces together equal the redacted whole answer (text is released only at safe cuts, with a 64 KiB hold cap); a conversation is titled from its first message.
- The core redactor now also hides secrets with spaces around the delimiter (`password = x`) and after `Bearer` with extra spaces or a tab.
- `agent::ToolContext` is now built through a constructor (`new`, with `with_plans` and `with_memory` for the optional seams) instead of struct literals, so adding a seam no longer breaks every caller.
- `db` hashes the audit chain with the `sha2` crate instead of in-house SHA-256 (decision 0012); decisions 0008, 0009 and 0010 are accepted.
- `.gitignore` now covers local databases, `measure.json`, and tool scratch directories.
- CI now has a `perf-budget` job (Linux and macOS) that builds the prototype, measures it with `scripts/measure.sh` and fails when `scripts/check-budget.py` finds a metric over `docs/perf-budget.json`.
- `db` now uses `rusqlite` 0.43 with its own `user_version` migrator instead of `rusqlite_migration` (decision 0011); a database newer than the build is refused.
- `cargo-deny` allows workspace path dependencies; the docs check skips `ui/node_modules`.
- Replaced `chunks_exact` with `as_chunks` in the SHA-256 code and removed an unused dependency from `i18n`, found by the latest stable clippy.
- Contributor rules: documentation is updated in the same change, and commits are pushed right after they are made when the owner asks for a commit; CI must be green after each push; toolchain and dependencies track the latest stable versions.

### Removed

- The M0 probe `ui/` and crate `proto-server` (ADR 0036). The colour tokens moved to `web/src/tokens.css`; `docs/perf-budget.json` and the CI `perf-budget` job now cover only the real `infra` binary.

### Fixed

- `infra serve` installs its shutdown handlers before it prints the sign-in address, so a signal right after startup stops it cleanly (it could kill the process on macOS CI).
