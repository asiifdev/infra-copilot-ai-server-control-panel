# Langkah berikutnya: serah terima ke sesi implementasi

Terakhir diperbarui: 2026-11-24 (setelah server lokal dan UI web, keputusan 0029-0031; skema masih versi 9; 843 tes lulus dan 1 diabaikan (uji hidup penyedia AI) lewat `cargo test --workspace`, ditambah 214 tes di `web/` lewat `npm test`). Dokumen kerja internal (Indonesia).

## Yang sudah ada

- Repo publik dengan CI hijau (fmt, clippy, tes di Linux dan macOS, `cargo deny`, `cargo audit`, gitleaks, pemeriksaan dokumen, dan job `web`: periksa tipe, tes, build, ukuran bundel, biner dengan UI tertanam, uji asap) dan perlindungan cabang `main`.
- Crate `core-domain` (tingkat risiko dan penyaring rahasia), 25 tes, tanpa dependensi luar.
- Crate `i18n` (katalog en/id), `db` (skema SQLite, kini versi 9 / migrasi 0001-0009, isolasi tenant, audit berantai-hash), dan prototipe `proto-server` + `ui/` dengan `scripts/measure.sh` (langkah 1-5 M0 selesai; keputusan 0007-0013 diterima; angka anggaran Linux menunggu kalibrasi).
- Server lokal dan UI web: crate `server` dan `bootstrap`, `infra serve`, `web/` (lihat langkah 6c).
- Dokumen: `docs/design.md`, `docs/plan.md`, `docs/decisions/0000-0032`, `docs/market-research.md`, `docs/RELEASE-CHECKLIST.md`.
- Konfigurasi pengembangan AI: `CLAUDE.md`, skill (parity-rules, ai-tool-tiers, migration-planning, security-review, repo-hygiene, rust-conventions, tauri-v2-*, svelte), hook `tauri-guard`, plugin Svelte (MCP dikunci 0.1.31).

## Memulai sesi implementasi

1. Buka sesi Claude Code di folder repo. `CLAUDE.md` dan skill terbaca otomatis. **Buka `/hooks` sekali** (atau mulai ulang) agar hook `tauri-guard` aktif.
2. Baca `CLAUDE.md`, `docs/design.md`, dan keputusan 0002-0006. Jangan memilih sendiri hal yang masih terbuka (di bawah).
3. Untuk setiap pustaka, **verifikasi dengan dokumentasi terkini (Context7)**, bukan ingatan. Untuk Tauri, muat skill `tauri-v2-*` dulu. Untuk Svelte, ikuti skill dan jalankan autofixer.
4. Jalankan `python3 scripts/check-docs.py` dan `./scripts/check-personal-data.sh` sebelum commit yang menyentuh dokumen. Commit: Conventional Commits berbahasa Inggris, `git commit -s`, tanpa atribusi Claude.

## Tugas M0 (urutan usulan)

1. **Evaluasi pustaka inti Rust** (server HTTP, runtime async, akses SQLite/PostgreSQL, serialisasi, logging, klien HTTP, SSH). Catat pilihan dan alasan sebagai keputusan baru di `docs/decisions/`, dengan dampak ukuran biner. Selesai: 0007 (diterima).
2. **Struktur workspace:** tambah crate sesuai `rust-conventions` (db, api, agent, collectors, parity, i18n, ...). Pertahankan dependensi sesedikit mungkin (prinsip 0005). Selesai: `i18n` dan `db`; crate lain menyusul per tahap.
3. **Katalog i18n (en, id)** dengan kunci stabil, dan uji yang menolak teks tampilan yang ditulis tetap. Selesai (0008).
4. **Prototipe pengukuran:** satu halaman tabel di Svelte 5 + Vite (tanpa SvelteKit) ditanam ke satu biner Rust. Ukur ukuran bundel, ukuran biner, memori diam, dan waktu mulai. Jadikan angkanya **anggaran kinerja** yang diperiksa di CI. Pengukuran selesai (0010); pemeriksaan di CI sudah dipasang (`scripts/check-budget.py`, `docs/perf-budget.json`, job `perf-budget`); angka Linux menunggu kalibrasi dari run CI.
5. **Skema database** (`docs/design.md` bagian 3) sebagai migrasi, SQLite lebih dulu, dengan uji isolasi tenant. Selesai (0009, 0012); pustaka AES-256-GCM untuk enkripsi rahasia belum dievaluasi.
6. **M1** (dipecah; **M1-a selesai**, ditambah PAR-006 beserta deteksi mode dev dan supervisor pada kolektor proses: kontrak `inventory`, kolektor Linux `listeners`/`processes`/`cron`, aturan PAR-001/006/008/010, CLI `infra collect|compare`, ADR 0013. **Modul D (bagian 1) selesai**: crate `net` (klien HTTP/TLS, 0016), `monitor` (mesin insiden murni) dan `notifier` (kontrak channel + Telegram kirim); **perekat `watch` selesai** (mesin probe-insiden-alert, sumber token sementara 0018); **belum**: perintah CLI/server yang menjalankannya, pengiriman ulang alert yang tertahan jam tenang, penyimpanan insiden di DB, perintah dan tombol bot, pengaturan persetujuan Telegram (bawaan tingkat 0-2, tingkat 3-4 tidak pernah lewat bot; dikerjakan bersama Usulan di M2/M4), kenaikan anggaran biner saat klien tertanam. **Modul C selesai** (item `env_ref`, PAR-002/007/009, keputusan 0015). **Modul B selesai**: kolektor systemd, docker, pm2 dan pelaksana perintah terbatas (0014). **Belum**: M1-b monitor uptime, mesin alert, bot Telegram; M1-c agen/SSH; kolektor systemd/docker/pm2/env_ref/database; aturan lain dari 11 aturan; uji di Linux nyata di luar CI). Rencana awal: kolektor inventaris Linux read-only, tiga aturan kesetaraan pertama dengan fixture anonim, monitor uptime dasar, mesin alert, dan bot Telegram.
6a. **M2 (asisten AI hanya-baca, ADR 0020, diterima)**: **M2-a selesai** (crate `agent`: kontrak `AiTool`, skema argumen ketat, registri berbatas tingkat 1, eksekutor dengan redaksi, pemotongan, dan pembungkus data tak tepercaya). **M2-b selesai** (migrasi 0004, `ReadStore` + `DbStore`, lima alat tingkat 0, uji isolasi tenant). **M2-c selesai kecuali uji hidup**: `vault` (0021, migrasi 0005), `net` dengan header dan SSE, crate `ai` (0022, 42 tes termasuk uji soket nyata); **belum dijalankan terhadap Muse/OpenAI/Ollama** (butuh kunci dari pemilik: `AI_BASE_URL=... AI_API_KEY=... AI_MODEL=... cargo test -p ai --test end_to_end -- --ignored`). **M2-d selesai** (0023, migrasi 0006): modul `agent::assistant` (maksimal 6 putaran alat lalu satu panggilan akhir tanpa alat, 8 panggilan per putaran, 20 pesan terakhir, anggaran token per giliran, satu giliran berjalan per percakapan lewat klaim, teks pengguna diredaksi sebelum disimpan atau dikirim, setiap panggilan alat diaudit, giliran butuh keanggotaan yang berlaku), `DbProviderLoader` (baris `ai_providers` + kunci `vault` + `ai::ProviderConfig`), alat tingkat 1 `propose_fix` yang hanya menulis Usulan `pending`, registri `assistant_registry`. **M2-e selesai** (0026, migrasi 0009): tabel `memories`, `search_docs` dan FTS5 `search_fts` yang disinkronkan pemicu database; alat `search_inventory` dan `list_memories` (tingkat 0) dan `remember` (tingkat 1, hanya membuat memori `pending`; hanya orang yang menyetujui, lewat `infra memory approve`); blok "catatan organisasi" di prompt sistem (maksimal 20 catatan aktif, 4 KiB, dipagari sebagai data); CLI `infra`: `init`, `node add`, `collect --save --node`, `compare --save --source-node --target-node`, `provider add|list|remove` (kunci API dari stdin atau `NODIVARA_PROVIDER_KEY`, tidak pernah argumen; kunci utama dari `NODIVARA_MASTER_KEY`), `ask`, `memory list|pending|approve|delete`, opsi global `--db`/`--org`, env `NODIVARA_DB`. Kode keluar: 0 berhasil, 1 temuan kritis atau cutover terblokir, 2 penggunaan/konfigurasi/IO, 3 asisten atau penyedia gagal. **Belum**: uji hidup penyedia (Muse/OpenAI/Ollama; ada uji `--ignored` yang belum pernah dijalankan), jalur persetujuan dan eksekusi Usulan (M4), Telegram sebagai antarmuka asisten (UI web lokal ada sejak langkah 6c), login multi-pengguna untuk CLI (kini bertindak sebagai pemilik org, mode lokal satu pengguna), pencarian semantik (embedding), pencarian frasa atau awalan.
6b. **M3 (perencana migrasi)**: **M3-a selesai** (crate `plan`, murni tanpa I/O, 0024, migrasi 0008): spesifikasi rencana ketat, urutan langkah dan gerbang pemadaman server lama, `gate_report`, saran kapasitas, pengecualian bawaan yang selalu dicetak, `draft_plan`, `render_plan` berlokal; perbaikan tinjauan: pola pengecualian yang cocok dengan semuanya ditolak dan konsistensi node di spec dengan baris DB diperiksa. **M3-b selesai** (crate `transport`, 0025, migrasi 0007): validasi `TransportSpec` per jenis (rclone, rsync, scp, ssh_pipe; `managed` dideklarasikan tetapi belum didukung), rencana perintah dengan rahasia hanya di lingkungan atau stdin dan daftar opsi rclone yang diizinkan per backend, seam `Runner` (`FakeRunner`, `ProcessRunner`; tidak pernah diarahkan ke host nyata dalam uji; batas waktu tidak lagi bergantung pada EOF pipa), mesin keadaan wizard dengan saran berlokal. **M3-c selesai** (0027): seam agen `PlanStore`/`PlanSink` dengan implementasi berbasis DB, alat tingkat 1 `draft_migration_plan` (hanya menulis rencana `draft`), alat tingkat 0 `show_plan`, `list_plans`, `check_plan_gates`, `list_transports`; registri asisten kini 14 alat; tidak ada alat yang bisa menyetujui, menjadwalkan, atau menjalankan apa pun. **M3-d selesai** (0028): `infra plan draft|list|show|gates` (satu jalur kode dengan alat AI, `agent::plan_flow`; tidak ada perintah setujui/jalankan; `gates` keluar 1 selama cutover terblokir) dan `infra transport add|list|show|remove|check` (kredensial hanya dari stdin `--credentials-stdin`, disegel `vault`; `check` secara bawaan uji coba yang mencetak rencana perintah dengan rahasia ditutup, hanya `--run` yang menjalankan lewat `ProcessRunner` di mesin ini; rclone tidak pernah dipasang produk, hanya ditawarkan). **Belum**: eksekusi rclone/rsync/scp/ssh sungguhan (seluruh jalur jalan baru diuji dengan `FakeRunner`; frasa galat rclone masih heuristik; M4), perintah memperbarui kredensial transport (sementara hapus lalu tambah lagi), kebijakan yang memblokir endpoint transport privat/loopback bila perintah berjalan di infrastruktur bersama (Cloud; wajib sebelum eksekusi terkelola M4/M6, endpoint di jaringan milik pengguna sendiri sah), sandbox tingkat OS untuk pelaksana proses, pengukur kapasitas nyata, UI untuk menyunting/menyetujui rencana (peninjauan hanya-baca sudah ada di UI web, langkah 6c). Pemeriksaan gitleaks lokal kini ada (`scripts/check-secrets.sh`).
6c. **Server lokal dan UI web (0029, 0030, 0031), selesai 2026-11-24**: crate `server` (axum 0.8, tokio, rust-embed; API JSON dan `web/dist` tertanam; hanya loopback, alamat lain ditolak) dan crate `bootstrap` (pembantu penyiapan yang dipindah dari `cli`: lokasi database, satu organisasi lokal, vault dari lingkungan, penyedia dengan kunci tersegel); perintah `infra serve [--port N] [--db PATH] [--org SLUG]` mencetak `http://127.0.0.1:PORT/#t=<token>` (token 256 bit, sekali pakai, berlaku 10 menit, di fragmen URL), cookie sesi `HttpOnly` `SameSite=Strict` (8 jam tanpa aktivitas, maksimum 5 sesi), pemeriksaan `Host`/`Origin`/`X-Nodivara`, CSP ketat, tanpa endpoint yang mengembalikan rahasia (kunci penyedia hanya diterima dan disegel); tanpa TLS dan tanpa login sungguhan (sesi berakhir karena menganggur, keluar, atau restart; pengguna yang keluar harus menjalankan `infra serve` lagi). UI di `web/` (Svelte 5 + Vite + TypeScript, tanpa SvelteKit, tanpa dependensi runtime): Ringkasan, Node (+ inventaris), Temuan, Asisten (obrolan mengalir dengan chip alat), Rencana (teks draf, tabel langkah, gerbang; tanpa setujui/jalankan), Transport, Memori (setujui/hapus catatan), Pengaturan (formulir penyedia, Uji koneksi, bahasa, tema); teks dari katalog Rust (kunci `ui.*`, rute publik `GET /api/i18n/{locale}`); 214 tes web; bundel produksi sekitar 131 KB JS (41 KB gzip) dan 15,5 KB CSS (3,2 KB gzip); diperiksa di Chromium (terang, gelap, 375 px, keyboard). Skrip: `scripts/build-web.sh`, `scripts/demo-serve.sh [--fake-ai]` (data demo sementara, penyedia palsu `scripts/fake-openai.py` di loopback), `scripts/smoke-serve.sh`, `scripts/check-secrets.sh` (gitleaks lokal). Perubahan perilaku yang menyertai: penyedia pertama sebuah organisasi otomatis menjadi bawaan (CLI dan server); teks rencana menyebut nama node dan transport, bukan id; teks asisten yang mengalir diredaksi sehingga potongannya sama dengan keseluruhan yang diredaksi (batas tahan 64 KiB); percakapan diberi judul dari pesan pertamanya; penyaring rahasia inti kini juga menutup rahasia dengan spasi di sekitar pemisah (`password = x`) dan setelah `Bearer` dengan spasi berlebih atau tab; opsi kredensial rclone ditolak sebagai opsi transport biasa. **Belum**: akses jarak jauh dan TLS, login sungguhan dan multi-pengguna, persetujuan dan eksekusi Usulan dan rencana (M4), uji hidup penyedia AI (tombol "Uji koneksi" di UI dan uji `--ignored` ada tetapi hanya pernah jalan terhadap tiruan loopback; langkah berikutnya yang paling berharga: jalankan dari UI dengan kunci Muse dari pemilik), kebijakan pemblokir endpoint transport privat di infrastruktur bersama, pemeriksaan di mode kontras tinggi Windows dan pembaca layar nyata, angka Linux untuk anggaran kinerja biner `infra` (blok `infra` di `docs/perf-budget.json`, keputusan 0032, macOS sudah diukur; kalibrasi dari run CI pertama), SVG merek resmi (`web/public/favicon.svg` adalah gambar ulang sementara), pensiun `ui/` dan `proto-server` setelah anggaran dihitung ulang.
7. Cangkang Tauri tipis menyusul setelah M1-M2 (skill `tauri-v2-*`, command dibatasi `AppManifest::commands`).
